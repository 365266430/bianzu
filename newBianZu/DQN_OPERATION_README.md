# DQN 动态编组操作流程

## 1. 按钮含义

| 按钮 | 作用 |
| --- | --- |
| 训练模式 | 开启 DQN 学习。系统会写入经验、更新 Q 网络，并允许 epsilon-greedy 探索。 |
| 推理模式 | 使用当前模型做决策，不再写入经验，不再训练，epsilon 固定为 0。 |
| 保存模型 | 将当前 DQN 网络参数保存到本地模型文件。 |
| 加载模型 | 从本地模型文件恢复 DQN 网络参数。 |
| 全部待命 | 将所有武器节点状态设为 `0`，允许参与动态编组。 |
| 全部分配中 | 将所有武器节点状态设为 `1`，主要用于测试，不建议正常训练时使用。 |
| 自动驻防 | 根据当前武器、保护区和威胁关系补充保护区的 `stationedWeaponIds`。 |
| 状态 | 查看当前 DQN 经验数、训练步、模型保存状态、运行模式等信息。 |

## 2. 状态字段含义

点击“状态”后，常见显示如下：

```text
DQN 状态：经验 5，训练步 15，模型已保存。
```

含义：

| 字段 | 含义 |
| --- | --- |
| 经验 | replay buffer 中已有的训练经验数量。 |
| 训练步 | DQN 网络已执行的训练更新次数。 |
| 模型已保存 | 当前已经存在本地模型文件。 |
| 模型未保存 | 当前还没有模型文件，或尚未触发保存。 |

注意：训练步不一定等于经验数。一次训练可能从经验池中采样多条经验并执行多次网络更新。

## 3. 推荐操作流程

### 3.1 首次训练

1. 启动 Redis。
2. 启动后端服务。
3. 启动前端页面。
4. 确认系统中已有：
   - 武器节点
   - 敌方目标
   - 保护区
   - 弹药类型和武器类型数据
5. 点击“全部待命”。
6. 点击“自动驻防”。
7. 点击“训练模式”。
8. 启动仿真，或多次生成动态编组方案。
9. 点击“状态”，观察：
   - 经验数是否大于 0
   - 训练步是否大于 0
   - 模型是否已保存
10. 训练一段时间后，点击“保存模型”。

推荐顺序：

```text
全部待命
-> 自动驻防
-> 训练模式
-> 启动仿真
-> 状态
-> 保存模型
```

### 3.2 使用已有模型进行推理

1. 启动 Redis。
2. 启动后端服务。
3. 启动前端页面。
4. 点击“加载模型”。
5. 点击“推理模式”。
6. 点击“全部待命”。
7. 点击“自动驻防”。
8. 生成动态编组方案。

推荐顺序：

```text
加载模型
-> 推理模式
-> 全部待命
-> 自动驻防
-> 生成动态编组方案
```

推理模式下不会继续训练，也不会写入新经验，适合验证当前模型的决策效果。

### 3.3 重新训练

如果需要从头训练：

1. 点击“重置 DQN”。
2. 点击“全部待命”。
3. 点击“自动驻防”。
4. 点击“训练模式”。
5. 启动仿真或生成动态编组方案。
6. 点击“状态”观察训练进度。
7. 训练稳定后点击“保存模型”。

推荐顺序：

```text
重置 DQN
-> 全部待命
-> 自动驻防
-> 训练模式
-> 启动仿真
-> 状态
-> 保存模型
```

## 4. 武器状态说明

武器节点状态字段为 `status`：

| 状态值 | 含义 | 是否建议参与训练 |
| --- | --- | --- |
| `0` | 待命 Idle | 是 |
| `1` | 分配中 Assigned | 通常不作为初始状态 |
| `2` | 被调度分配中 Engaging | 通常不作为初始状态 |

正常训练前应点击“全部待命”，确保武器状态为 `0`。

不建议在正常训练流程中点击“全部分配中”。该按钮主要用于测试状态接口。

## 5. 保护区驻防关系说明

保护区字段 `stationedWeaponIds` 表示当前与保护区关联的武器节点 ID。

当前逻辑分为两类：

| 类型 | 说明 |
| --- | --- |
| 自动驻防 | 根据当前武器和保护区关系进行一次初始化分配。 |
| 动态回写 | 仿真过程中，根据红方目标威胁的保护区，将本轮分配的武器回写到对应保护区。 |

动态编组中的关系可以理解为：

```text
红方目标
-> 判断其威胁哪个保护区
-> DQN/动态编组选择武器拦截该红方目标
-> 武器动态归属到该保护区
```

因此，`stationedWeaponIds` 不只是静态配置，也会随着仿真动态变化。

## 6. 模型保存与加载

模型文件保存的是当前 DQN 网络参数。

常见接口：

```text
POST /dqn/save
POST /dqn/load
GET  /dqn/status
POST /dqn/mode?mode=TRAIN
POST /dqn/mode?mode=INFER
```

后端启动时会自动尝试加载模型文件。可以通过“状态”查看：

| 字段 | 含义 |
| --- | --- |
| `modelFile.exists` | 模型文件是否存在。 |
| `modelFile.loadedOnStartup` | 本次后端启动时是否成功加载模型。 |
| `modelFile.lastLoadMessage` | 最近一次加载结果。 |

如果不确定是否加载成功，可以手动点击“加载模型”。

## 7. 常见问题

### 7.1 状态显示经验为 0

可能原因：

- 武器状态不是 `0`
- 武器没有弹药
- 没有敌方目标
- 敌方目标没有高度 `altitude`
- 没有保护区
- 没有可执行的武器-弹药-目标候选动作

处理：

```text
全部待命
-> 自动驻防
-> 启动仿真
-> 状态
```

### 7.2 模型未保存

可能原因：

- 训练步还不够
- 没有产生经验
- 后端没有写入模型文件权限

处理：

- 先确认经验数和训练步大于 0。
- 点击“保存模型”手动保存。
- 再点击“状态”确认模型是否已保存。

### 7.3 推理模式下经验不增加

这是正常现象。

推理模式用于验证模型，不用于训练，因此：

- 不写经验
- 不更新网络
- epsilon 为 0
- 总是按当前模型评分选择动作

### 7.4 点击“全部分配中”后没有方案

这是正常的。

动态编组通常只选择 `status = 0` 的武器参与分配。如果所有武器都是 `1`，可能没有可用武器。

处理：

```text
点击“全部待命”
```
